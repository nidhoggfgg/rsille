# rsille 3.3.0

Inline apps can now draw Kitty images alongside shell output. Both Kitty and Sixel
ship with the default build. The renderer, Unicode canvas and TUI are also available
as individual crates. This release includes breaking changes for 3.2 users.

## Inline graphics

- On Unix, before starting input, call `RasterBackend::Auto.negotiate_inline(...)` and pass
  the resulting `InlineRasterSession` to `.inline_raster_session(...)`. Inline
  Auto selects Kitty. On a Sixel-only terminal, select `RasterBackend::Sixel`
  explicitly after confirming that images scroll with text, erasing a row clears
  its graphics, and positioned output is safe. Fullscreen Auto still prefers
  Kitty and falls back to Sixel.
- Transparent pixels now compose consistently in inline and fullscreen frames.
  With `Chunk::raster`, they show the image's configured background, even if text
  occupied the cell in the previous frame. With `Chunk::raster_overlay`, they
  reveal the text underneath in the current frame.
- Apps that manage their own terminal output can import `KittyImage` from
  `rsille::raster::output`. Use `draw_offset` to position RGBA pixels within a
  terminal cell and `place_offset` to move the image without uploading it again.

## Upgrading from 3.2

| If your app uses… | Change for 3.3 |
| --- | --- |
| The `rsille` crate | Set `rsille = "3.3.0"`. The existing `rsille::render`, `rsille::canvas` and `rsille::tui` paths re-export the three component crates. You can also depend directly on `rsille-render`, `rsille-canvas` or `rsille-tui`, each at version `0.1.0`. |
| The `sixel` or `kitty` Cargo feature | Remove the old feature names. The default `raster` feature enables both protocols, `RasterCanvas` and the `raster_canvas` widget. |
| `default-features = false` | Text and Unicode Canvas work with this setting. Add `features = ["raster"]` if you use pixel graphics, including offscreen drawing or sampling with `RasterCanvas`. |
| `syntax-highlighting` or `CodeViewer::language` | Remove the old feature and method. For plain text, use `code_viewer(source)`. For highlighted code, add the companion crate `rsille-syntect` and use `CodeViewer::from_lines(rsille_syntect::highlight(source, "rs"))`. Highlight once when the source changes and reuse the styled lines across redraws. [Extension source and example](https://github.com/nidhoggfgg/rsille/tree/v3.3.0/packages/rsille-syntect) |

## Playground

The separately released `rsille-playground` bundles the function plotter, AI
Babies, DeepSeek pet and jellyfish demos in one `rsille` executable. Run it
with no arguments to list the commands, or try these from the repository root.

```sh
cargo run -p rsille-playground -- draw
cargo run -p rsille-playground -- ai-babies --kitty
cargo run -p rsille-playground -- pet -- vim README.md
```

- The function plotter draws inline with Kitty or Sixel. Live previews and
  exported images now show the graphs alone, and the plotter no longer pulls in
  Typst for formula labels.
- On Unix with Kitty graphics, the DeepSeek pet stays interactive when a wrapped
  program such as Vim switches to the alternate screen. Drag the whale, open its
  menu to blow bubbles, or feed it a fish and watch it burp. Its movement now
  targets 30 fps and advances in pixels between terminal cells. It can transform
  into a blue whale and keep chasing the pointer even after it stops moving.
  Sixel sessions hide the pet on the alternate screen and restore it on return.
